# 爆款拆解框架（用于 LLM 分析）

> 这份文件是 Claude（或任意 LLM）分析 `sources.jsonl` 时的**评分与拆解规则**。
> 采集脚本只负责"抓什么"，这份框架负责"为什么爆"。
> 规则借鉴了小红书选题策划社区常见的"人群×场景×痛点×情绪×钩子"拆解法，
> 以及账号相对表现的等级判定思路，但这里的判断要**基于证据**，不许编造。

## 0. 输入与输出

- 输入：`data/<日期>-<关键词>/sources.jsonl`（每行一条候选爆文，含标题/正文摘要/互动/标签/时间/IP/URL；若开了 `--detail`，还含 `comments` 评论区与 `detail` 详情）。
- 输出：`data/<日期>-<关键词>/analysis.md`（报告）+ 可选 `analysis.json`（结构化）。

### 数据边界（重要，先看这个再分析）

每条笔记可能只有部分字段，按下面的"证据等级"使用，**缺失的字段不许脑补**：

| 字段 | 说明 | 证据价值 |
|---|---|---|
| `title` / `desc` | 标题 + 搜索接口返回的正文摘要 | 钩子、情绪、结构（核心证据） |
| `liked_count` / `collected_count` / `comment_count` / `share_count` | 互动数字 | 互动结构（核心证据） |
| `comments[]` | 评论区（采集时默认抓取，每条前 N 条） | **人群、痛点、情绪、共鸣（最直接的爆因证据）** |
| `detail` | 完整详情（若含 `detail_unavailable: true` 说明详情接口被风控） | **通常被风控不可用**，有则用，无则跳过正文级拆解 |
| `comment_error` | 评论抓取失败的原因 | 说明该条无评论证据 |
| `tags` / `upload_time` / `ip_location` | 标签/时间/IP | 辅助 |

- **详情接口需带 `xsec_token` 的完整 URL**：采集时用 `explore/{id}?xsec_token=...` 调用，能正常拿到正文全文（存在 `detail.desc`）。若个别笔记 `detail_error` 或 `detail_unavailable: true`，说明该条详情仍被风控，拆解时只用标题+互动+评论并标注"该条无正文证据"。
- **评论区是最重要的证据**：`comments[]` 里有真实用户的原话、点赞数、昵称。分析"为什么爆"时优先引用评论——高赞评论、共鸣评论、争议评论是判断人群/痛点/情绪的最可靠来源。
- 互动数字来自接口返回值，已归一为 int（`1.2万`→`12000`）。

## 1. 单条笔记拆解（对每条候选）

按下面六个维度逐条输出，每个结论必须给出**证据**（原文片段/数字），拿不准就写"证据不足"。

| 维度 | 要回答的问题 | 证据来源 |
|---|---|---|
| 人群 | 这条在写给谁？（年龄/身份/场景） | 标题、desc、评论区 |
| 场景 | 在什么时刻/处境下被需要？ | 标题、desc |
| 痛点 | 戳中了什么焦虑/渴望/未满足需求？ | desc、评论区共鸣 |
| 情绪 | 标题和内容调动什么情绪？（共鸣/好奇/冲突/焦虑/爽/厌恶损失…） | 标题、desc、评论情绪 |
| 钩子 | 让人点进来的第一眼设计？（数字悬念/人群标签/冲突句/结果前置…） | 标题、封面文字（若 detail 有） |
| 结构 | 正文怎么组织？（清单式/故事式/对比/教程/避坑…） | desc；若 detail 可用则看全文，`detail_unavailable` 时只基于 desc 推断并标注"基于摘要" |

### 互动结构观察
- 点赞/收藏/评论/分享**四者比例**说明了什么？
  - 收藏占比高 → 干货型（"先马后看"），人们想留档。
  - 评论占比高 → 争议/共鸣型，评论区是主战场。
  - 分享占比高 → 身份表达/利他型，人们愿意转发给特定的人。
- 评论区在聊什么？有没有二次衍生话题、求链接、站队？

## 2. 单条评分（1–10 分）

| 分数 | 含义 |
|---|---|
| 8–10 | 现象级爆款（T3）：绝对互动高 + 评论区有强共鸣/争议，可作模板逐条复刻 |
| 5–7 | 稳定爆款（T2）：互动高于该品类常见水平，结构清晰可复用 |
| 3–4 | 潜力款（T1）：数据一般但有明确可放大的钩子/角度 |
| 1–2 | 普通款：证据不足以支撑"爆"，可能是搜索顺带返回的 |

判定用证据（互动绝对量 + 评论共鸣强度 + 结构完整度），不要凭感觉。产出每条 `{score, tier, 一句话理由}`。

## 3. 品类级总结（报告核心）

对整批候选做聚合，输出四段：

1. **热点分布**：这批内容在哪些子方向/角度上扎堆？给出子方向 → 笔记条数 → 代表笔记。
2. **爆款公式**：把得分 5+ 的笔记的共性提炼成**可复用模板**，例如：
   `目标人群标签 + 具体数字/结果 + 情绪词 + 实操清单/避坑/对比`
   每条公式给 1–2 个来自证据的例证。
3. **空白机会**：用户画像（如果提供） vs 现有内容——有哪些"有需求但没被做好"的角度？哪些子方向竞争激烈但同质化？
4. **可复刻选题**：基于公式产出 3–5 个具体选题（标题骨架 + 内容方向 + 为什么可能爆）。

## 4. 硬性纪律

- **不许编造**：所有互动数字、评论内容必须来自 `sources.jsonl`。数据缺失就写"该字段未采集"，不要脑补。
- **不许泛泛而谈**：每条结论尽量引用原文或数字。
- 区分"这个品类火了"与"这条笔记火了"——单条爆文可能是偶然，多条的共性才是趋势。
- 如果用户给了账号画像或筛选意图，分析要回扣到"适不适合我"；否则只做客观拆解。
