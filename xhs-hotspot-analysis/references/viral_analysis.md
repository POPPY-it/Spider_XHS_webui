# 爆款共性提取框架（Creator Buddy 方法，用于 LLM 分析）

> 本文件是 LLM 分析 `sources.jsonl` 的规则。采集脚本负责"抓什么"，本框架负责"为什么爆、能不能复刻"。
> 方法来源：Creator Buddy「爆款共性提取」——用 A/B 双标签给每篇内容定性，再横向数共性，最后把共性落成可执行清单。所有判断必须基于证据，禁止编造。

## 0. 输入与数据边界（先读这个）

输入：`sources.jsonl`，每行一条，字段可能只有部分，按"证据等级"使用，缺失不许脑补：

| 字段 | 说明 | 证据价值 |
|---|---|---|
| `title` / `desc` | 标题 + 搜索接口返回摘要；`detail.desc` 为完整正文 | 钩子/结构/形态（核心） |
| `liked_count`/`collected_count`/`comment_count`/`share_count` | 互动数字 | 互动结构（核心） |
| `comments[]` | 每条含 `content`/`like_count`/`nickname` | **爆因证据最强：共鸣、痛点、争议、人群原话** |
| `detail` | `detail.desc` 完整正文 | 有则用；`detail_unavailable`/`detail_error` 表示被风控 |
| `fans`/`ratio`/`is_lowfan` | 作者粉丝、互动/粉丝比、低粉爆款标识 | 判断「是否可复制」的关键 |
| `keyword`/`tags`/`upload_time`/`ip_location`/`image_count`/`note_type` | 辅助 | 赛道词、人群地域 |

- **评论区是最强证据**：分析"为什么爆"时优先引用高赞评论、共鸣评论、争议评论的**原话**。
- **详情被风控**（`detail_unavailable`/`detail_error`）→ 只用 title+interact+comments，并标注"该条无正文证据"。
- **互动数字已归一为 int**（`1.2万`→`12000`）。

## 1. 标签 A · 内容形态（这是一篇什么内容；可多选，标出最主导的 1 个）

清单盘点 / 教程步骤 / 测评对比 / 个人经历 / 避雷吐槽 / 数据结论 / 资源合集 / 身份背书。
判定看结构：分点列清单→清单；按步骤走→教程；同场对比→测评；第一人称叙事→个人经历；劝退/排雷→避雷吐槽；给结论/数字→数据结论；一次性给足可保存的→资源合集；靠职业/头衔背书→身份背书。

## 2. 标签 B · 爆款机制（为什么会被推；每条只取 top 1-2）

- **新鲜感**：说清新在哪（角度/组合/时间段），不要只说"很新颖"。
- **结果感**：数字锚点，开头三行就给出数字/结果。
- **场景感**：锁死具体场景，少讲概念多讲"何时用/在哪用"。
- **身份感**：用人群标签聚人（"新手妈妈""大厂 HR"）。
- **情绪感**：用读者原话当标题，触发共鸣/好奇/焦虑/爽。
- **反差感**：先立认知再推翻（"没想到""原来""越 X 越 Y"）。
- **收藏动机**：内容里能有"能截图带走"的（模板/清单/攻略）。
- **争议感**：立场鲜明/二选一/劝退（注意合规风险，不鼓励）。

## 3. 单条拆解输出格式（对每条候选）

```
### [序号] title
- 证据：评论原话（带赞数）或 title/desc 原文片段；无正文时标注"基于摘要"
- 内容形态（A）：X（主）｜Y
- 爆款机制（B）：X｜Y（top1-2）
- 评分：8–10 现象级｜5–7 稳定｜3–4 潜力｜1–2 普通
- 一句话理由：为什么爆 + 是否可复制
```
评分判定：8-10=绝对互动高+评论区强共鸣/争议，可作模板；5-7=高于该品类均位、结构清晰；3-4=数据一般但有明确可放大的钩子；1-2=证据不足以支撑"爆"。**用证据，不凭感觉。**

## 4. 数共性（对整批做分布，输出三条线）

1. **形态分布**：`清单 9/20｜测评 5/20｜教程 3/20…`（按标签 A 计数）。
2. **机制分布**：`收藏动机 12/20｜身份感 9/20｜结果感 6/20…`（按标签 B 计数，每条可计 1-2 个）。
3. **标题高频词**：去掉停用词和赛道词后，按出现次数取前 10-14 个——这些词就是该赛道的搜索入口。

**判定阈值**：≥40% = 真共性（可当赛道规律）；20-40% = 次主流，可差异化切入；<20% 且仅 1-2 条支撑 = 个例，**别包装成趋势**。

## 5. 拆三张清单

**① 可复用清单**（不依赖特殊身份/独家数据/高成本拍摄 → 可迁移到普通账号）——每条给：共性描述 + 对标笔记链接（`url`）+ 换到用户赛道怎么落地。
**② 不可复用清单**（身份壁垒：三甲医生/大厂HR/十年从业；资源壁垒：独家数据/样品堆/高成本场地/明星资源）——说明"谁做不到、为什么"。
**③ 平台适配建议**（针对该赛道在平台分发上的适配点：封面/首图/评论区运营/搜索词布局）。

## 6. 用户补充背景

若用户提供了账号画像/目标品类（`--context` / `--target-category`），分析要回扣到"适不适合我/能不能迁移到目标品类"。目标品类与当前关键词不同时，build_prompt 会另追加「跨品类迁移建议」，按第 5 节"可复用/不可复用"的思路，提炼这批爆款的【钩子】【结构】【情绪】【人群】哪些能迁过去，并给改写标题与套用结构的具体示例。

## 7. 硬性纪律

- **不许编造**：所有互动数字、评论内容、标签必须来自 `sources.jsonl`；缺失写"该字段未采集"。
- **每条结论尽量引用原文或数字**，不泛泛而谈。
- 区分"这个品类火了"与"这条笔记火了"——单条爆文可能是偶然，**多条共性才是趋势**。
- 评论证据优先于 desc；`fans`/`ratio`/`is_lowfan` 用于判断"能否被普通账号复刻"。
